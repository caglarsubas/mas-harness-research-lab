## 1. Hypotheses (falsifiable)

H-27a (determinism): two runs of the same class with the same seed produce byte-identical effect logs (every row, every field, serialised with sorted keys). Unit: one (class, seed) pair; 13 classes x 32 seeds = 416 pairs. Gate: PASS when every pair is identical; FAIL when any pair differs; UNRESOLVED when fewer than 39 pairs were produced (3 seeds per class) or the export's `classes.json` digest does not match the committed results (precondition, evaluated first for every claim).

H-27b (the harness's own replay class): the committed class row of C3 (kind REPLAY_STALE, the campaign's replayed and stale messages) reproduces exactly on the pin: the lab's `ledger.class_row` output equals the committed row in `results.json` under RL-03's comparison (sorted-key JSON equality of the whole row). Gate: PASS when equal; FAIL when not; UNRESOLVED only under the precondition.

H-27c (duplicated and stale replays refused): after a run ends, replaying an accepted board operation (a) with the same operation id answers DUPLICATE_ID and changes no state, and (b) for the versioned operations (ACQUIRE, ASSIGN, RENEW, RELEASE, MERGE) with a fresh operation id and the original `expectedVersion` (the reordered case: the operation arrives after the version moved) is refused (any answer other than ACCEPTED) and changes no state. Unit: one replay attempt; the attempts are every BOARD_ANSWER row with answer ACCEPTED and no `retryOf` in the first run of every (class, seed) pair, replayed at the run's deadline tick through the same simulation's board (`Board.apply(deadline, op)`), the operation rebuilt from the row's fields (agent, to, item, op, opId, expectedVersion, claimOpId, workDigest, event). "Changes no state" = the logged `changed` field is false. Gate: PASS when every duplicate answers DUPLICATE_ID with `changed` false and every stale replay is refused with `changed` false, and the driver raised no exception; FAIL when any duplicate is answered otherwise, or any stale replay is ACCEPTED, or any replay has `changed` true; UNRESOLVED when no attempt could be posed, or when the lab's driver raised an exception on any attempt (an instrument gap: the vector set is then incomplete and the uncovered attempts are counted), or under the precondition.

Overall verdict: PASS when H-27a, H-27b and H-27c all PASS; FAIL when any FAILs; UNRESOLVED otherwise. Expected outcome class, stated in advance: PASS on all three (the harness was built with these refusals, and RL-03 reproduced four class rows exactly); a FAIL on H-27c would be a finding against the board's dedupe or version rule.
